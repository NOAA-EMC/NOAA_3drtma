
Build instructions

1. Clone the `3DRTMAv1` branch of the NOAA_3drtma repository into a packages subdirectory:
```
mkdir packages
cd packages
git clone -b 3DRTMAv1 https://github.com/NOAA-EMC/NOAA_3drtma rtma3d.v1.0.0
```

2. Copy the fix and parm files:
```
cd rtma3d.v1.0.0
cp -r /lfs/h2/emc/da/noscrub/matthew.t.morris/packages/rtma3d.v1.0.0/fix/* fix/
cp -r /lfs/h2/emc/da/noscrub/matthew.t.morris/packages/rtma3d.v1.0.0/parm/* parm/

or run the script util_dev/cpln_fixparm.sh, or use that script as a reference.
```

3. Move to the sorc directory:
```
cd sorc
```

4. Build the RTMA3D workflow:
```
./build_rtma3d_all.sh
```

5. Install the executables
```
./install_rtma3d_all.sh
```

6. Change user.name in the workflow/*xml files


7. Some __Important Options/Parameters__ which user might need to chanage when setting up the parallel system
    - **i_gsd_terrain_match_mesonet**
   ```
    description: applying GSD terrain match to mesonet obs of T (188/195, and 192/193)
	user needs to change:
		scripts/conus/exrtma3d_gsianl.ksh
		scripts/alaska/exrtma3d_gsianl.ksh
	i_gsd_terrain_match_mesonet=0
	0: do not apply terrain match to additional types of sfcobs of t (default)
	1: apply terrain match to additional types of sfcobs of t (188/192/193/195)
	   value 1 is considered but not recommended for 3drtma yet,
	   because lots of mesonet obs of t are rejected, and 2-m q is not adjusted.
    ```
    - **i_gsdsfc_uselist**
   ```
	description: using GSD MESONET obs uselist and AIRCRAFT report rejectlist or
	                AutoQC MESONET obs uselist and AIRCRAFT report rejectlist.
	user needs to change:
		scripts/conus/exrtma3d_gsianl.ksh
		scripts/alaska/exrtma3d_gsianl.ksh
	i_gsdsfc_uselist=2  (2 is default, but Aircraft rejectlist by AutoQC is still in experimental test.)
	1: using MESONET use list and AIRCRAFT reject list generatd by GSL daily
		gsd_sfcobs_uselist.txt is read in GSI, instead of sfcobs_uselist.txt (which is gnerated by AutoQC);
		GSL aircraft rejectlist is copied to gsi running direcory as "current_bad_aircraft", and replace the
		AutoQC aircraft rejectlist.
	2: using MESONET use list and AIRCRAFT reject list generatd by Matthew Morris's AutoQC hourly (experimental)
		sfcobs_uselist.txt, which is generated by AutoQC, is read in GSI, instead of gsd_sfcobs_uselist.txt;
		GSL aircraft rejectlist is NOT copied to gsi running direcory. So the "current_bad_aircraft" is
		the aircraft rejectlist generated by AutoQC.
   ```
    - **i_cch260_rtma**
   ```
	description: select the algorithm to compute cliud ceiling height parameter 260
	user needs to change:
		scripts/exrtma3d_post.ksh
		scripts/exrtma3d_post4fgs.ksh
	i_cch260_rtma=0 (default. reulst of 1 might be better, but still under investigation.)
	in calculation of parameter 260 of cloud ceiling height:
	0: using the original Ferrier's cloud ceiling algorithm to compute cloud base height;
	1: using the GSD legacy cloud ceiling algorithm to compute cloud base height, same as in parameter 408 of CCH;
		if using 1, then calculation of 260 is "contaminated" by calculation of 408, which happened in old UPP
		for old 3DRTMAv1;
   ```
    - **RUN_UPDATEP**
   ```
	description: updating pressure fields in analysis (wrf_inout)
	user needs to change:
		workflow/rtma3d_pbspro_conus.xml
		workflow/rtma3d_pbspro_alaska.xml
	RUN_UPDATEP="No"
	"No/no/False/false": default: no updating pressure fields in analysis (wrf_inout)
	"Yes/yes/True/true": updating pressure fields in analysis (wrf_inout)
   ```
